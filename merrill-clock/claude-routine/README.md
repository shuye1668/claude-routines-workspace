# Claude Remote Routine 設定

## 這個排程做什麼

每個美股交易日，在美國開盤前：

1. 讀取 Google 文件「**美林時鐘 每日摘要**」（由 Apps Script 每日更新，含機器可讀 JSON）
2. 做深度關鍵分析：時鐘讀數可信度、轉折確認狀態、四類背離、風險結構、配置意涵與失效條件
3. 依警示等級（🔴／🟡／⚪）寄出 Email

## 前置條件與上線順序

1. Apps Script 端完成部署（`setup_StoreSecrets()` → `refresh_Calibration()` → `backfill_History(3)`）
2. 執行 `run_ExportDigest()`，確認雲端硬碟出現「美林時鐘 每日摘要」文件
3. 在 Routines 介面為排程掛上 Google Drive 與 Gmail
4. Apps Script 每日觸發器設在台北上午 6–7 點

順序反了也不會壞：排程會在步驟 0／步驟 1 偵測到並回報缺什麼。

## 排程時間：為什麼是台北早上、而且是週二～週六

### FRED 這七條序列全都是盤後資料

| 序列 | 內容 | 可取得時間 |
|---|---|---|
| `VIXCLS` | VIX 收盤價 | 美東收盤後當晚 |
| `T10Y2Y` | 10Y−2Y（來自 H.15 殖利率曲線） | 美東傍晚（財政部公布後） |
| `BAMLH0A0HYM2` | ICE BofA 高收益債 OAS | 隔夜／隔日美東早上 |
| `DFF` | 有效聯邦基金利率 | 隔日美東早上發布**前一營業日**的值 |
| `CFNAIMA3`／`CPIAUCSL`／`CPILFESL` | 月頻 | 發布日美東 08:30 |

**沒有盤前更新這回事。** 所以要「確保當日資料發布完成」，正確的時點是美東傍晚之後——
換算成台北就是隔天早上 6 點之後。

### 星期對齊：是週二～週六，不是週一～週五

Apps Script 的週末防線是用**美東**星期判斷的（`Utilities.formatDate(new Date(),'America/New_York','u')`）。
台北早上 07:00 = 美東前一天 19:00，所以：

| 台北 | 美東 | 結果 |
|---|---|---|
| 週二～週六 07:00 | 週一～週五 19:00 | ✅ 執行，處理前一交易日收盤 |
| 週日 07:00 | 週六 19:00 | 自動略過（無新資料） |
| 週一 07:00 | 週日 19:00 | 自動略過（週五收盤已在週六處理完） |

若 Claude 排程照直覺設成「週一～週五」，會在**台北週一空跑**（Apps Script 已略過、資料是舊的），
而且**漏掉台北週六**——也就是漏掉整個週五收盤的判讀。

### 實際設定

| 環節 | 時間 | 說明 |
|---|---|---|
| Apps Script 每日觸發器 | 台北 **上午 6–7 點**（設每日即可） | 週日／週一會自己略過 |
| Claude Routine | 台北 **週二～週六 08:23**（UTC cron `23 0 * * 2-6`） | 留給 Apps Script 約 80 分鐘餘裕 |

> **上線後第一週要驗一件事**：高收益債 OAS（`BAMLH0A0HYM2`）是 ICE 授權資料，
> FRED 的更新時點比其他幾條晚。若你發現試算表的「高收益債利差」在台北早上跑的那一列
> 經常比 VIX 落後一天，把 Apps Script 觸發器改到台北晚上 9–10 點（＝美東早上 9–10 點）即可補上；
> 這時 Claude 排程要跟著改成台北週二～週六的更晚時段，或直接改成美股盤前時段。
> 程式本身對此是安全的——它一律取「最新可得」的值，不會因為某條序列落後就整列失敗。

## 與 Apps Script 的信件如何分工

- **Apps Script**：只在偵測到轉折或跨越警示門檻時，寄一封快速的「事件通知」（純數據、無 AI）。
- **Claude routine**：每個交易日寄一封深度分析信，等級 ⚪ 時會刻意寫得很短。

兩者不重複：Apps Script 那封是「發生了什麼」，Claude 這封是「所以呢」。
若覺得太多，把指令碼屬性 `ALERT_EMAIL` 留空即可停掉 Apps Script 端的信。
