# 美林投資時鐘 V4 — 邏輯拆解、問題與優化

從 V3.1 的三份 Apps Script 出發，重新檢視資料流、判讀邏輯與呈現方式，並把每日深度分析
接到 Claude Remote Routine 上。

---

## 1. 這套系統原本在做什麼

```
FRED API ──► Apps Script (Code.gs)  ──► Google 試算表（每交易日一列）
   7 個序列        每日抓數、分類、算分           │
                                                 ├─► Index.html 網頁面板（SVG 時鐘）
                                                 └─► Gemini 產報告 ──► Email
Backfill.gs：以 as-of 方式重算歷史，補「歷史解讀」與「象限轉折」
```

兩組互相獨立的判讀：

| | 用什麼 | 回答什麼問題 |
|---|---|---|
| **水準象限** | `g = CFNAI-MA3`、`inf = CPI年增率 − 2.5%` 的正負號 | 你**在哪** |
| **方向階段** | 兩者的 3 個月動能 `Δ3m` 的正負號 | 你**往哪去** |

方向階段才是美林原始框架（Recovery → Overheat → Stagflation → Reflation 順時針），
資產建議也是由它推出來的。

## 2. 原本的問題

### 2.1 「指針的長短看不懂」— 因為它本來就沒有意義

V3.1 的畫法是：

```js
const G_SCALE = 1.5, INF_SCALE = 4;
x = 200 + (inf / INF_SCALE) * 160;
y = 200 - (g   / G_SCALE)   * 160;
mkLine(plot, 200, 200, cur.x, cur.y, '#ffd54f', 2, 1);   // ← 這條就是「指針」
```

從圓心拉到座標點的那條線，長度是 `√((inf/4)² + (g/1.5)²)`。兩軸各自除以 4 和 1.5——
這兩個數字彼此無關、也沒有任何統計意義，所以**長度是一個混合單位，不能解讀、也不能跨時間比較**。
真正的時鐘只有角度有意義，這條線卻同時混進了一個無法解釋的長度。

更麻煩的是後面還有 `clamp(x,18,382)`：座標超出範圍時點會被壓在邊界上，
**指針長度會失真而畫面上完全看不出來**。

同時，橘色動能箭頭被強制正規化成固定 32px：

```js
const len = Math.hypot(vx, vy) || 1;
mkArrow(plot, cur.x, cur.y, cur.x + (vx/len)*32, cur.y + (vy/len)*32, '#ff7043');
```

方向有了，但**動能大小整個被丟掉**——時鐘轉得快還是幾乎沒動，看起來一模一樣。

### 2.2 水準象限長期誤判

`levelQuadrant_` 用 `CFNAI > 0` 判定「成長高於趨勢」。但 CFNAI-MA3 的 0 是
**1967 年以來的趨勢成長**，近 20 年的實際常態中位數在 0 以下。結果 2023–2024 明明是軟著陸，
水準象限卻長期顯示「滯脹」——這個試算表裡的「歷史解讀」欄自己就寫了：

> 「水準顯示滯脹是 CFNAI 偏低假象，以方向階段為準。」

一個需要靠註解來否定自己輸出的欄位，是邏輯問題，不是註解問題。

### 2.3 `ZERO_BAND` 是症狀不是解法

V3.1 用 `|g| ≤ 0.05` 把貼近 0 軸的轉折標為「暫定」。方向對，但只處理了成長軸、
沒處理通膨軸，門檻 0.05 也是拍腦袋定的、和資料的實際波動無關。

### 2.4 風險分數是階梯函數

`vixR` 在 15 有一個斷點，VIX 從 14.9 走到 15.1，總分直接跳 9 分。
資料裡滿滿的 `53（中性）` ↔ `62（中性）` 就是這樣來的——**那不是風險變了，是門檻被跨過了**。

### 2.5 軌跡取樣頻率錯了

總經是月頻、日間只是平移。V3.1 畫「最近 12 個交易日」的軌跡，
等於 12 個點幾乎疊在同一個位置，看不出時鐘有在轉。

### 2.6 其他

- 金鑰硬寫在程式碼裡（註解自己承認已外洩）。
- 日頻序列用 `limit=1`：遇到美國假日的 `"."` 空值會解析成空陣列，當天整條資料掉光。
- 核心 CPI 抓了但完全沒用在框架裡——油價衝擊期間這正是最該看的東西。
- Gemini 呼叫沒有重試，`json.candidates[0]` 在被擋時會直接丟例外。

## 3. V4 的改法

### 3.1 指針長度＝離中性多少個標準差（核心修正）

兩軸都改用 **z 分數**標準化，中性點與尺度都取自資料本身（近 20 年穩健統計：
中位數與 `1.4826 × MAD`，對 2020 那種極端月不敏感）：

```
成長z  = (CFNAI-MA3 − 近20年中位數) / 穩健σ
通膨z  = (CPI年增率 − 2.5 − 近20年中位數) / 穩健σ

指針角度 = atan2(通膨z, 成長z)，從正北順時針 → 換算成鐘面時刻
指針長度 = √(成長z² + 通膨z²)，單位 σ
```

兩軸單位一致之後，長度才是一個真正的距離，而且有明確意義：

| 指針長度 | 意義 | 該怎麼用 |
|---|---|---|
| `< 0.5σ` | 中性帶 | 象限標籤幾乎沒有資訊量，任何一個月的雜訊都能讓它翻面 |
| `0.5 ~ 1.0σ` | 偏弱 | 結論要帶條件句 |
| `≥ 1.0σ` | 明確 | 可以給方向性配置傾向 |
| `≥ 2.0σ` | 極端 | 反而要回頭檢查是不是單一衝擊造成的離群值 |

錶面上畫出 1σ／2σ／3σ 三個虛線圈當尺，中心 0.5σ 是灰色的「中性帶」圓盤。
**指針長度可以直接對著圈讀。** 超過 3σ 不再偷偷截斷，而是畫一個紅色箭頭並標出真實數值。

### 3.2 兩根針，都從圓心出發

| | 代表 | 角度 | 長度 |
|---|---|---|---|
| **時針**（金） | 你在哪 | 景氣時刻 | 離中性多少 σ ＝訊號強度 |
| **分針**（橘） | 你往哪去 | 動能朝向哪個時刻 | 轉多快（σ／3 個月），**不再被正規化掉** |
| **鬼影針**（青虛線） | 拿掉油價後的位置 | — | 與時針分很開就是背離，**方向決定意涵**（見下） |

兩針的夾角本身就是一個讀數，面板上直接算給你看：

- 夾角 `< 45°` → **體制強化**（點正在往外跑，離中性越來越遠）
- 夾角 `45°–135°` → **轉檔中**，並用外積判斷是**順時針**（符合美林循環）
  還是**逆時針**（反常，通常是地緣／政策這類外生衝擊，不是內生循環）
- 夾角 `> 135°` → **回歸中性**

這是原本那張圖完全給不出來的資訊。

鬼影針的背離要看方向，兩種情況的政策意涵相反：

- **整體高於核心** → 能源／食品推升的表面通膨，核心沒跟上。央行通常會看穿，除非外溢到核心。
- **核心高於整體** → 能源把表頭壓低、底層通膨仍黏著。「通膨回落」是假象，轉鴿空間比表頭看起來小。

（2023 年下半正是後者：核心 4.7% 高於整體 3.3%；2026 年油價衝擊則是前者。）

### 3.3 校準象限：中性點改成「近 20 年常態」

新增 `校準象限` 欄，以近 20 年穩健中位數為中性點；原本的 `景氣象限` 保留在旁邊供對照。

要說清楚的是：**這個修正是溫和的**（中位數大約落在 −0.05 ~ −0.15 之間，不會讓 2023 年
整段從滯脹翻成復甦）。真正解決「別再被象限標籤誤導」的，是 §3.1 的指針長度——
當指針只有 0.8σ、而且水準與方向背離時，面板會直接告訴你**這個標籤現在不可信**，
而不是硬給一個看起來很確定的四字結論。

### 3.4 轉折確認改成可證偽規則

丟掉 `ZERO_BAND`，改為：

- 轉折當日：指針 `≥ 1.0σ` → **確認**；否則 → **暫定**。
- 暫定的轉折若在**第 2 個總經資料版本**（下一版 CFNAI／CPI 發布後）仍維持同一象限
  → 自動升級為**確認(延後)**，並發一封確認信。
- 另外加註信用與波動的第二意見：`crossConfirm_()` 會判斷 OAS 20 日變化與 VIX
  是否同步確認這次轉折，或者總經與市場正在唱反調。

`同象限資料版本數` 欄記錄目前這段象限已經撐過幾版總經資料——這是判斷體制穩固度最直接的指標。

### 3.5 風險分數連續化

改為分段線性內插，權重 信用 0.40 ／ 波動 0.35 ／ 曲線 0.25，並輸出 `風險分項`（曲線／信用／波動）
讓你看得出是誰在主導。實測同一組輸入：

```
VIX 14.9 → 15.1（其餘不變）
  V3.1： 53 → 62   （憑空跳 9 分）
  V4  ： 46 → 46   （跳 0 分）
```

### 3.6 其他修正

- 軌跡改成按**總經資料版本**取樣（最近 18 版），時鐘的轉動終於看得見；轉折點標 ⚡。
- 日頻序列改抓 40 筆，避開假日空值，順便算出 `信用動能Δ20d`、`VIX動能Δ20d`——
  總經是月頻，日頻的增量資訊全在信用與波動這兩條上。
- 核心 CPI 正式進入框架（`核心inf分數`／`核心通膨z` ＋ 鬼影針）。
- 金鑰移到「指令碼屬性」，程式碼裡不再有明文。
- 每日警示改為**邊緣觸發**（只在跨越門檻當天通知），避免持續狀態天天寄信。
- `ensureHeaders_` 改為依欄名搬移既有資料，欄位順序變動不會造成錯位。
- Gemini 呼叫加上三次重試與安全的回應解析；預設關閉（深度分析交給 Claude routine）。

## 4. 資料流（V4）

```
FRED ──► Code.gs ──► 試算表（40 欄）──► Index.html 面板
                │
                ├──► 「校準」分頁：σ 與中位數（指針長度的單位來源）
                ├──► Google 文件「美林時鐘 每日摘要」（人類摘要 + 機器可讀 JSON）
                │         └──► Claude Remote Routine 每個交易日讀取
                │                  └──► 深度關鍵分析 ──► Email 警示
                └──► 事件即時通知信（只在有轉折／警示時，不含 AI，快）
```

職責切分：**Apps Script 負責取數與即時事件通知；Claude routine 負責深度判讀。**
兩邊不重複寄信。

## 5. 部署步驟

1. 三個檔案覆蓋原本的 `Code.gs`、`Index.html`、`Backfill.gs`。
2. **先到 FRED 與 Google AI Studio 重新產生金鑰**（舊的兩把已外洩），
   編輯 `setup_StoreSecrets()` 內的四個 `PASTE_...` 值，執行一次。
3. 執行 `refresh_Calibration()`，到「校準」分頁確認 σ 與中位數已寫入。
4. 執行 `backfill_History(3)` 重算歷史（會清空並重寫所有資料列，含「歷史解讀」欄）。
5. 執行 `run_ExportDigest()`，確認 Google 雲端硬碟出現「美林時鐘 每日摘要」文件。
6. 重新部署網頁應用程式，開啟面板確認新的鐘面。
7. 建立每日觸發器指向 `run_MerrillLynchTracker`，時間設在**台北上午 6–7 點**。
   FRED 這七條序列全是盤後資料（VIX 收盤、H.15 殖利率曲線、ICE OAS、DFF 隔日發布），
   台北早上才拿得到完整的前一交易日資料。台北週日與週一會被美東週末防線自動略過——
   這是對的，因為那兩天本來就沒有新的收盤資料。

> 回填會覆寫「歷史解讀」欄。若你在該欄有手動編輯過的內容，回填前請先備份分頁。
> 每日執行（`upsertByDate_`）則會沿用既有值，不會洗掉手動欄位。

## 6. Claude Remote Routine 設定

見 [`claude-routine/ROUTINE_PROMPT.md`](claude-routine/ROUTINE_PROMPT.md)。
排程需要 **Google Drive** 與 **Gmail** 兩個連接器：前者讀摘要文件，後者寄警示信。
排程時間為**台北週二～週六 08:23**——注意是週二到週六，不是週一到週五，
原因（FRED 發布節奏與美東星期對齊）寫在該資料夾的 README。

資料來源優先用 Google 文件（不需額外部署）；若想改用 JSON 端點，
網頁應用程式支援 `?api=digest&token=<API_TOKEN>&days=60`，token 在指令碼屬性裡。

## 7. 已知限制

- **CFNAI-MA3 會回溯修正。** 芝加哥聯準銀行每月會修正前幾期數值，
  所以歷史列的 z 分數在回填後可能與當初即時計算時不同。這是資料本身的性質，不是 bug。
- **框架是月頻的。** 日與日之間的變化幾乎只來自 VIX、OAS、利差三條日頻序列。
  時鐘位置一個月只真正動一次。
- **20 年校準窗包含 2020。** 已用 MAD 而非樣本標準差來降低敏感度，但若你認為
  該期間應排除，可在 `computeCalibration_()` 調整窗期或加上篩選。
- **`assetByPhase_` 是美林原始框架的教科書對應**，未做任何回測驗證，屬教育用途。
- 高收益債 OAS 序列起始於 1996，回溯更早期間時該分項會缺席（風險分數自動改用其餘分項的加權）。
